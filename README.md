# Sub Converter

Android 端 mihomo (Clash Meta) 订阅转换与管理工具。在手机本地运行 HTTP 服务，将多个订阅源聚合、筛选后输出统一的 mihomo 配置。

## 功能

- **订阅源管理** — 添加多个 mihomo 订阅 URL，查看流量、到期信息，支持自动定时刷新
- **正则筛选** — 对节点名称设置保留/排除正则，带实时预览匹配结果
- **覆写系统** — 管理多个 YAML 覆写，支持远程 URL 自动拉取更新、全局启用和优先级排序
- **输出配置** — 将多个订阅源 + 全局/专属覆写组合为输出订阅，其他客户端直接订阅
- **本地 HTTP 服务** — 在手机上启动 HTTP Server，局域网内其他设备可直接拉取配置
- **自动识别** — 从订阅响应头自动获取名称 (`profile-title`)、官网地址 (`profile-web-page-url`)，输出时携带标准头

## 技术栈

- Kotlin + Jetpack Compose + Material 3
- Room (数据库) + DataStore (设置)
- OkHttp (网络请求) + SnakeYAML (YAML 解析)
- WorkManager (定时刷新) + Coroutines/Flow

## 构建

```bash
./gradlew assembleDebug
```

Debug APK 输出路径: `app/build/outputs/apk/debug/`

## 使用

1. 添加订阅源（URL），首次刷新自动获取名称和流量信息
2. 按需创建 YAML 覆写，用于追加规则、替换分组或调整 DNS 等配置
3. 创建输出配置，选择订阅源和专属覆写
4. 启动 HTTP 服务，用其他客户端订阅输出的 URL

## 正则筛选

订阅源支持 **保留** 和 **排除** 两个正则，用于按节点名称过滤。筛选逻辑：

1. 若 **保留** 为空，则所有节点默认保留；否则只有名称匹配保留正则的节点保留
2. 若 **排除** 不为空，名称匹配排除正则的节点会被移除
3. 最终结果 = 保留 ∩ 排除的反集

正则使用 Kotlin `Regex`（即 Java 正则语法），采用**部分匹配**（`containsMatchIn`），不需要写完整的节点名。

## YAML 覆写

覆写会在基础 mihomo 配置生成后按顺序合并。执行顺序为：全局覆写列表顺序 → 输出配置里的专属覆写顺序。同一个覆写同时出现在全局和专属列表时只执行一次。

- 普通对象字段会深合并
- 普通数组字段会整体替换
- `+rules` 将数组内容追加到现有数组开头
- `rules+` 将数组内容追加到现有数组末尾
- `proxy-groups!` / `dns!` 会整体替换对应字段

### 示例

假设节点列表：

```
香港 01 | 倍率x1.0
香港 02 | 倍率x1.0
日本东京 01
美国洛杉矶 01
新加坡 01 | 倍率x2.0
台湾 01
```

| 保留 | 排除 | 结果 | 说明 |
|------|------|------|------|
| `香港` | | 香港 01, 香港 02 | 匹配包含"香港"的节点 |
| `香港\|日本` | | 香港 01, 香港 02, 日本东京 01 | `\|` 表示或 |
| `香港\|新加坡` | `01` | （无） | 先保留含"香港"或"新加坡"的，再排除含"01"的 |
| `香港\|日本\|新加坡` | `倍率` | 日本东京 01 | 保留三个地区，排除含"倍率"的 |
| | `倍率x2` | 香港 01, 香港 02, 日本东京 01, 美国洛杉矶 01, 台湾 01 | 不设保留（全部保留），排除高倍率节点 |
| `(?i)US\|HK` | | （取决于节点名是否含 US 或 HK） | `(?i)` 忽略大小写 |

> **提示**：输入正则时界面会实时预览匹配结果，蓝高亮 = 匹配，灰暗 = 被过滤，输入框下方显示匹配节点数。如果正则语法有误会显示红色提示。

## 输出示例

```
http://<IP>:9876/subscriptions/1.yaml?token=xxx
```

响应头包含:
- `Profile-Title` — 订阅名称
- `Profile-Web-Page-Url` — 官网地址
- `Profile-Update-Interval` — 更新间隔（小时）
- `Subscription-Userinfo` — 流量信息
- `Content-Disposition` — 文件名
